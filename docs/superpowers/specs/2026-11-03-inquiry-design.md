# 문의함 설계 (web 문의하기 · admin 문의함)

- 작성일: 2026-11-03
- 범위: BE `inquiry` 도메인 신설 + web(교육생) 문의하기 + admin 문의함

## 목표

교육생(회원·비회원)이 서비스 관련 문의를 남기고 답변을 확인한다. 관리자는 운영 메뉴의
문의함에서 답변하고, 미해결 문의 수를 사이드바 뱃지로 본다.

## 확정한 요구사항

| 항목 | 결정 |
|---|---|
| 비회원 답변 확인 | 작성 시 비밀번호 설정 → 성명+연락처+비밀번호로 내 문의 목록·상세 조회 |
| 숫자 뱃지 | 미해결(답변 안 된) 문의 수 — 모든 관리자 계정에 동일 |
| 작성 범위 | 교육생은 작성만. 수정·삭제·댓글·첨부 없음. 관리자 답변 1개(수정 가능) |
| 문의 유형 | 교육내역(누락·정정) · 확인서 발급 · 결제·환불 · 본인인증·로그인 · 진위확인 · 기타 |
| 과거 문의 | admin 답변 화면에서 같은 문의자의 다른 문의를 모아 본다 |

## 데이터 — `inquiries` (답변을 같은 행에 둔다)

- `category` · `title`(≤100) · `content`(≤2000) · `status`(`open` / `answered`)
- 작성자: `user_id`(회원, nullable) · `trainee_id`(연결된 감리원, nullable)
- 작성 시점 문의자 정보(회원·비회원 공통으로 채움): 성명 암호화+해시, 연락처 암호화+해시,
  감리원증번호, 이메일. 회원은 회원 정보에서 자동으로, 비회원은 입력값으로.
- 비회원: `password_hash` (기존 pbkdf2)
- 답변: `answer` · `answered_by`(admin) · `answered_at`
- 같은 문의자 판정: `user_id` 일치 **또는** (성명 해시 + 연락처 해시) 일치 —
  회원 문의에도 해시를 남겨 로그인 전(비회원) 문의와 합쳐 보인다.
- 연락처 해시는 키 있는 HMAC (이름 blind index 와 같은 이유 — 키스페이스가 작다).

## API

| 대상 | 경로 |
|---|---|
| 회원 | `POST /api/me/inquiries` · `GET /api/me/inquiries` |
| 비회원 | `POST /api/public/inquiries` · `POST /api/public/inquiries/lookup` |
| 관리자 | `GET /api/inquiries` · `GET /api/inquiries/unresolved-count` · `GET /api/inquiries/{id}` · `PUT /api/inquiries/{id}/answer` |

- 회원 API 는 PASS 로그인 세션(`get_current_user`)만 요구 — 감리원 연결 심사 중인 회원도 문의할 수 있다.
- 비회원 작성·조회는 IP 기준 rate limit, 작성 폼 honeypot(봇이면 성공한 척 응답).
- 비회원 조회 실패는 어느 값이 틀렸는지 알리지 않는다("일치하는 문의가 없어요").
- 답변 등록·수정은 감사 로그(`inquiry.answered`).

## 화면

- web 회원: 사이드바 "문의하기" → `/inquiries` (내 문의 · 새 문의 작성). 성명·감리원번호·연락처 자동(읽기 전용).
- web 비회원: 헤더 "문의하기" → `/inquiry` (문의 남기기 · 내 문의 조회). 로그인 상태면 `/inquiries` 로 보낸다.
  비회원 입력: 성명*·연락처*·감리원증번호·이메일·비밀번호*(숫자 6~20자리)+확인·개인정보 수집 동의*.
- admin: 운영 > 문의함 `/inquiries` + 미해결 수 뱃지(1분 폴링·포커스 시 갱신).
  목록 필터(상태 기본 미해결·유형·회원/비회원·기간·검색) URL 상태, 서버 페이지네이션 20.
  상세: 문의 + 문의자 정보 + 답변 입력 / 같은 문의자의 다른 문의.

## 배포

새 테이블 → Alembic 마이그레이션. BE 먼저, 이후 web·admin.

## 테스트

BE 통합: 회원 작성 자동 정보 · 비회원 검증·해시 저장 · 비회원 조회 성공/실패/rate limit ·
타인 문의 비노출 · 답변 시 상태·미해결 수 · 같은 문의자 묶음(회원+비회원). FE: 타입 체크 + 흐름 확인.

## 보안 검수 반영 (독립 리뷰)

- 비회원 조회: 성공·실패 모두 IP 기준 + 대상(성명+연락처) 기준으로 원자적으로 센다(동시 요청·IP 회전 우회 방지).
  후보는 최대 20건, pbkdf2 는 스레드에서(워커 1개 이벤트 루프 보호), 일치 없음도 더미 검증으로 응답 시간 동일.
- honeypot 은 동의·횟수 검사 뒤 판별, 응답 형식 동일. 연락처·비밀번호는 NFKC 후 ASCII 숫자만.
- admin 과거 문의는 `matched_by`(account / name_phone) — 성명·연락처만 일치는 '미확인' 표시, 비회원 문의엔 본인확인 경고.
- 답변 수정 감사 로그에 수정 전·후 답변을 남긴다. admin 검색의 `%`·`_` 는 문자 그대로.
- 의도적으로 둔 것: admin 상세는 회신용으로 연락처 전체 표시, 회원 작성 횟수 제한 없음.
