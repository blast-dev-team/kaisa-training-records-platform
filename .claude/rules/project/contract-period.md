# 계약 기간 — 종료일은 시작일 + N개월 **− 1일**

12개월 계약이 **5/16** 에 시작하면 다음 해 **5/15** 에 끝난다. 5/16 이면 12개월 하고
하루다.

```
2026-09-11 시작 · 12개월  →  2027-09-10 종료      ✅
                          →  2027-09-11 종료      ❌ (12개월 + 1일)
```

---

## 왜 이 규칙인가 — 근거는 실계약이다

로컬 DB 의 계약 329건 중 시작일·기간·종료일이 다 있는 것을 세어 봤다.

| 형태 | 건수 | 정체 |
|---|---:|---|
| 시작일 + N개월 **− 1일** | 26 | **레거시에서 이관한 실계약** — 사람이 쓴 계약서 |
| 시작일 + N개월 (같은 일자) | 77 | 시스템이 `_calc_end_date` 로 만든 것 |
| 그 외 | 226 | 이관 시 손으로 넣은 자유 입력 |

이관분 26건은 전부 `−1일` 형태였다 (예: `2025-05-16 ~ 2026-05-15`, `2026-02-04 ~
2027-02-03`). **사람이 쓴 계약서가 맞고 우리 계산이 틀렸다.** 2026-08-21 에 규칙을 고쳤다.

> `total_months` 가 `61` 인 계약이 몇 건 있는데 실제 기간은 60개월이다(이관 시
> 경계 월을 양쪽 다 센 것으로 보인다). 규칙 문제가 아니라 데이터 quirk다.

## 하루가 틀리면 어디까지 번지나

종료일은 여러 판정이 딛고 서는 값이라 하루가 조용히 퍼진다.

| 딛고 서는 것 | 하루 밀리면 |
|---|---|
| 만기임박 (`days_to_return`) | 알림이 하루 늦는다 |
| 차량 점유 겹침 (`_intervals_overlap`) | back-to-back 계약이 **겹침으로 잡혀 차단**된다 |
| 재계약 시작일 기본값 (`nextDayYMD`) | 하루 뒤로 제안돼 기간에 구멍이 생긴다 |
| 운영 대시보드 시점 대수 | 경계일에 같은 차가 두 대로 세어진다 |

## 계산 순서 — **하루를 먼저 빼고 개월을 더한다**

말일이 낀 경우에만 순서가 결과를 바꾼다. 거꾸로 하면 두 가지가 깨진다.

```
① 더하고 −1 (❌)              ② −1 하고 더함 (✅ 이걸 쓴다)
  1/31 +1개월 → 2/28 → 2/27     1/30 +1개월 → 2/28
  3/31 +1개월 → 4/30 → 4/29     3/30 +1개월 → 4/30
  3/30 +1개월 → 4/30 → 4/29     3/29 +1개월 → 4/29
                 ↑ 뭉개진다                    ↑ 안 뭉개진다
```

①은 2월 말일로 잘린 뒤 하루가 **또** 빠져 한 달이 28일이 되고, 시작일이 다른 두
계약(3/30·3/31)의 종료일이 같아진다. ②는 `1/31 → 2/28`, `3/31 → 4/30` 으로
말일이 말일로 대응된다.

## 구현 — 한 규칙, 두 구현(BE·FE)

| | |
|---|---|
| 백엔드 | [`contract_service._calc_end_date`](../../../backend/api/app/domain/contract/service/contract_service.py) — 계약 생성·확정·출고완료·연장 **7곳이 전부 이걸 쓴다** |
| 프론트 | [`shared/utils/contract-period.contractEndYMD`](../../../frontend/apps/crm-fe/src/shared/utils/contract-period.ts) — 재계약 모달·사고대차 계약 수정이 쓴다 |

프론트에 **또 만들지 않는다.** 2026-08-21 정리 전까지 `calcEndDate` 사본이 **4개**
있었고 셋이 서로 달랐다.

| 있던 곳 | 무엇이 틀렸나 |
|---|---|
| 재계약 모달 | (신규 — 처음부터 공용 규칙) |
| 사고대차 계약 수정 | `Date.setMonth` **롤오버** — `1/31+1개월` 이 `2/31 → 3/3`, 하루 빼서 `3/2`(정답 `2/28`). **저장되는 값이었다** |
| 영업 계약 수정 | 같은 롤오버 버그 |
| 기존 계약 가져오기 | **구 규칙**(`+N개월`) — 서버가 저장할 값과 하루 어긋난 미리보기 |

## 상세와 모달의 종료일이 다르게 보인다면

출처가 다르다. **상세는 저장값**(`contract.end_date`)을 그대로 보여 주고, **수정
모달은 시작일+개월로 즉석 계산**해 "저장하면 이렇게 된다"를 보여 준다. 그래서
저장값이 옛 규칙으로 만들어졌거나 `total_months` 가 실제와 안 맞으면 두 값이 갈린다.

운영중 계약 318건 기준: 일치 25 · **하루 차이 68**(옛 규칙으로 저장됨) ·
**한 달 이상 차이 225**(`total_months` 가 1 큼).

영업 계약 수정 모달은 다를 때 `저장하면 … 로 바뀌어요` 로 **둘 다 보여 준다** —
조용히 다른 숫자를 띄우면 사용자가 화면을 못 믿는다.

화면이 미리 보여 준 종료일과 저장된 값이 다르면 사용자는 화면을 못 믿는다. **양쪽을
같은 케이스로 테스트한다** — 실계약 6건 + 말일 4케이스:

- BE [`test_contract_period.py`](../../../backend/api/app/domain/contract/test_contract_period.py)
- FE [`contract-period.test.ts`](../../../frontend/apps/crm-fe/src/shared/utils/contract-period.test.ts)

## 기존 데이터 실태 (2026-08-21 점검 · 로컬 기준)

계약 909건을 훑은 결과. **전부 2026-05-31 이관분**이고, 이후 운영에서 생긴 건은 없다.

| 상태 | 건수 | 판단 |
|---|---:|---|
| 출고됐는데 **종료일 없음** | 396 | 만기임박·차량 스케줄에서 빠진다 |
| `total_months` 가 실제보다 **1 큼** | 221 | 금액·청구는 0이라 지금 영향 없음. **수정하면 종료일이 한 달 밀린다** |
| 종료일이 구 규칙(`+N개월`) | 77 | 하루 길다 |
| 시작일이 자유 텍스트(`'6월30일'`) | 15 | 전부 출고 전 |

**`total_months` 로 종료일을 일괄 채우면 안 된다.** 종료일이 있어 검증 가능한 이관
계약 247건 중 221건(89%)이 `total_months` 가 1 컸다. 그 값으로 396건을 채우면
대부분 한 달 뒤 날짜가 들어간다. 원 계약서나 레거시 엑셀 대조가 먼저다.

## 산식을 화면에 적는다

종료일 옆에 `시작일 + 60개월 − 1일` 을 같이 보여 준다. 숫자만 있으면 그게 어디서
왔는지 알 수 없어, 다른 화면의 값과 다를 때 어느 쪽이 맞는지 판단할 수가 없다.
계약 상세·확정 모달·수정 모달이 모두 같은 문구를 쓴다.

## 종료일이 산식으로 정해지지 않는 경우

`end_date` 를 쓰는 모든 곳이 산식을 타는 건 아니다. **개념이 다른 것을 통일하려 들면 안 된다.**

| 경로 | 무엇이 들어가나 |
|---|---|
| 장기렌트 — 계약 생성·확정·출고완료·연장 | 산식(`_calc_end_date`). **여기만 통일 대상** |
| 사고대차 확정 | 사용자가 입력한 **반납 예정일** — 기간 개념이 없다 |
| 회수 처리 | 실제 **회수 일시** — 예정이 아니라 발생한 사실 |

## 체크리스트 — 계약 기간을 다루는 코드를 쓸 때

- [ ] 종료일을 직접 계산하지 않고 `_calc_end_date` / `contractEndYMD` 를 쓰는가
- [ ] 화면에 종료일을 보여 준다면 서버와 **같은 함수 규칙**인가
- [ ] 다음 계약 시작일은 **종료일 다음날**인가 (겹치지도 비지도 않게)
- [ ] 말일 시작(1/31, 3/31) 케이스가 테스트에 있는가

## 하지 말 것

- ❌ 종료일을 `시작일 + N개월` 로 계산 (하루 길다)
- ❌ FE 에서 `Date.setMonth(+N)` 로 즉석 계산 — **롤오버**라 `1/31+1개월` 이 `3/3` 이 된다
- ❌ 화면마다 종료일 계산을 따로 구현 — 공용 `contractEndYMD` 를 쓴다
- ❌ 이미 저장된 종료일을 이 규칙으로 **일괄 재계산** — 기존 계약은 그 계약서대로 둔다

> 기존에 `+N개월` 로 저장된 계약 77건은 그대로 둔다. 실제 계약서와 다를 수 있으므로
> 손대려면 계약서 대조가 먼저다 — 코드가 임의로 하루를 당길 일이 아니다.
