# PRD 버전 관리 워크플로우

`docs/crm/prd/` 에서 관리하는 CRM 기획 문서의 작성 규칙과 템플릿.

---

## 폴더 구조

```
docs/crm/prd/
├── CHANGELOG.md     ← 버전 메타 요약 (버전별 사유 + 이슈 처리 결과 + 변경 파일)
├── feedback.md      ← 전체 버전 피드백 통합 (## v1.0, ## v1.1 섹션으로 분리)
├── overview.md      ← CRM 전체 개요
└── {도메인}.md       ← PRD 문서 — 도메인당 파일 1개
```

- PRD는 **도메인당 파일 하나**. 버전 폴더(`v1.0/` 등)나 버전별 사본을 만들지 않는다.
- 보완 시 같은 파일을 **수정**하고 문서 헤더 `> 버전:` 을 올린다. 과거 버전은 git 이력으로 추적한다.
- 버전 번호는 레포 전체 PRD 릴리즈 통합 번호. 문서 헤더 `> 버전:`, CHANGELOG `## vX.X`,
  feedback.md 섹션이 같은 번호 체계를 공유한다. 새 도메인의 첫 PRD는 현재 릴리즈 버전을 단다.

## 워크플로우

```
① PRD 작성     기획자   {도메인}.md 작성 (> 버전: vX.X)
      ↓
② 피드백 작성  리뷰어   feedback.md의 해당 버전 섹션에 이슈 추가
      ↓
③ 보완         기획자   {도메인}.md 수정 + 헤더 `> 버전:` 올림 + CHANGELOG 항목 추가
      ↓
      반복
```

---

## 템플릿

### ① PRD 문서 — `{도메인}.md`

```md
# {도메인명} PRD

> 버전: vX.X  
> 작성자:  
> 작성일: YYYY-MM-DD  
> 상태: 초안 | 검토중 | 확정

---

## 1. 개요

한 줄 목적 설명.

## 2. 상태 정의 (상태머신 도메인일 경우)

| 상태 | 설명 | 진입 방식 |
|------|------|-----------|
| 상태명 | 설명 | 자동/수동 |

## 3. 주요 플로우

단계별 흐름 기술.

## 4. 제약 조건

- 허용되지 않는 전환 또는 액션
- 권한 제한

## 5. 미결 사항

결정이 필요하지만 이 버전에서 확정되지 않은 항목.
```

---

### ② 피드백 문서 — `feedback.md` (루트 통합 파일)

이슈 번호는 전체 PRD 히스토리에서 유일해야 함. 이전 버전의 마지막 번호에서 이어서 부여.

결정이 나면 해당 이슈 아래에 `**결정 (vX.X)**:` 섹션을 추가. 별도 파일 없이 이슈 제기부터 결정까지 한 곳에서 관리.

```md
# 피드백

전체 버전 피드백 이슈 통합 관리. 새 이슈는 해당 버전 섹션 아래에 추가.

---

## v1.0

> 작성자: · YYYY-MM-DD · 대상: {도메인}.md

### #N. {이슈 제목}

**문제**
구체적인 문제 상황 기술.

**실운영 영향**
이 문제가 실제 운영에서 어떤 결과를 낳는지.

**결정 필요 사항**
- A안 vs B안 등 선택지

> 이슈 처리 결과는 CHANGELOG `### 이전 이슈 처리` 섹션에 기록. feedback.md에는 별도 결정 섹션 추가 불필요.
```

---

### CHANGELOG.md 포맷

```md
## vX.X · YYYY-MM-DD
### 사유
이번 버전이 만들어진 이유. 한 단락.
### 이전 이슈 처리
- ✅ #N 이슈 제목 → 처리 내용 한 줄
- ⚠️ #N 이슈 제목 → 부분 처리 내용
- ❌ #N 이슈 제목 → 보류 이유 한 줄
### 변경
- `{도메인}.md` — 변경 내용 한 줄 요약
```

> **CHANGELOG vs feedback.md 역할 분리**  
> - CHANGELOG `### 이전 이슈 처리`: 한 줄 요약 (파싱 대상)  
> - `feedback.md` 이슈별 `**결정**` 섹션: 결정의 상세 맥락과 이유

---

## 이슈 번호 관리

- 이슈 번호는 `#1`부터 시작, 전체 버전 통틀어 유일
- 새 피드백 작성 시 이전 버전의 마지막 번호 + 1부터 부여
- 한 번 부여된 번호는 재사용하지 않음 (보류/삭제돼도 번호 유지)

```
## v1.0 섹션 → #1, #2, #3
## v1.1 섹션 → #4, #5, #6  (1부터가 아닌 4부터)
## v1.2 섹션 → #7, #8, ...
```
