# 반응형 · 브레이크포인트 규칙

사내 CRM 은 데스크톱 업무 도구다. 모바일까지 반응형을 끌고 가지 않는다.
대신 **최소 지원 폭을 정하고, 그 아래에서는 레이아웃을 찌그러뜨리지 말고 가로 스크롤**한다.

## 기준 폭

| 뷰포트 | 기기 | 정책 |
|--------|------|------|
| **1280 이상** | 노트북 13"(1280×800), 1366×768, MacBook | **스크롤 없이 지원** — 여기서 깨지면 버그 |
| 1440 | MacBook Air/Pro 기본 | 설계 기준 폭 |
| 1536 이상 | 외장 모니터 | `max-w-[1440px]` 로 이미 상한 |
| 1280 미만 | 창 좁힘·태블릿 | **가로 스크롤** (레이아웃 유지) |

### 콘텐츠 최소 폭 = 1024px

앱 셸([auth-layout.tsx](../../../frontend/apps/crm-fe/src/app/layouts/auth-layout.tsx))이
콘텐츠 열에 `min-w-[1024px]` 를 걸어 **전 화면에 자동 적용**된다. 페이지마다 따로 걸지 않는다.

```
뷰포트 1280 − 사이드바 220(펼침) − main 좌우 패딩 32 = 1028  ≥ 1024  → 스크롤 없음 ✅
```

사이드바가 접히면(64px) 여유가 더 생긴다.

### 레이아웃 모드와는 무관하다

라우트 `handle` 의 `fullWidth` / `wideLayout` 은 **높이·스크롤 소유권과 최대 폭**을 나누는
개념이다. 최소 폭은 그와 별개인 전역 정책이므로 **세 모드 모두 동일하게 적용**된다.

하한을 `main` 안쪽이 아니라 셸 최상단(콘텐츠 열)에 두는 이유가 이것이다. `fullWidth` 의
`main` 은 `overflow-hidden` 이라 안쪽에 하한을 두면 스크롤이 아니라 잘려 나간다.
셸에서 처리하면 모드 분기 없이 한 곳에서 끝난다.

## 브레이크포인트

Tailwind 기본값을 그대로 쓴다. **커스텀 브레이크포인트를 만들지 않는다.**

| 접두사 | 폭 | 이 프로젝트에서의 의미 |
|--------|-----|----------------------|
| `xl:` | 1280 | **기본 하한** — 대부분의 열 배치는 여기서 결정 |
| `2xl:` | 1536 | 넓은 화면에서 더 펼칠 때만 |
| `lg:` 이하 | ~1024 | CRM 화면에서는 거의 쓸 일 없음 |

> 접두사 없는 base 클래스는 **콘텐츠 폭 1024 기준**으로 동작한다고 보면 된다.
> 1024 에서 안 깨지는 열 수를 base 로 두고, 넓어지면 `xl:`/`2xl:` 로 늘린다.

## 열 수 정하는 법

카드 1장의 **최소 필요 폭**을 먼저 계산한다. 열 수를 먼저 정하지 않는다.

```
필요 폭 = 좌우 패딩 + 줄바꿈이 불가능한 가장 긴 조각

예) 6열 KPI 카드: 콘텐츠 1440 → 카드 185px → p-5 빼면 안쪽 145px
    이 145px 안에 들어가야 하는 것들을 하나씩 재고, 넘치면 줄인다.
```

**열 수를 줄이기 전에 내용을 먼저 의심한다.** 열을 줄이면 한눈에 보이는 밀도를 잃는다.
실제로 영업 대시보드 KPI 에서 가장 넓었던 건 금액(≈144px)이 아니라
`whitespace-nowrap` 이 걸린 델타 라벨 `전주 대비 (7.28~8.3) ▲16.8%`(≈169px)였다.

| 줄이는 수단 | 예 |
|---|---|
| 줄바꿈 허용 | `whitespace-nowrap` 제거, `flex-wrap` 추가 |
| 축약 표기 + 원값 hover | `₩8,745,000,000` → `₩87.5억` + `title` |
| 열 수 축소 | 위 둘로 안 될 때 마지막 수단 |

```tsx
// ✅ 6열을 유지하되 카드 안 내용이 145px 에 맞도록 줄였다
<div className="grid grid-cols-6 gap-4">

// ✅ 내용을 줄일 수 없을 때만 열 수를 낮춘다
<div className="grid grid-cols-3 2xl:grid-cols-6 gap-4">

// ❌ 폭 계산 없이 열 수만 정함 — 좁아지면 글자가 잘린다
<div className="grid grid-cols-6 gap-4">   // 안에 nowrap 169px 짜리가 들어있다면
```

## 고정 폭 패널이 여러 개인 화면 (상세 3분할 등)

`w-[300px] shrink-0` 같은 패널이 여러 개면, 가변 영역은 **남는 것만** 받는다.
셸 하한(1024)은 페이지가 붕괴하는 것만 막을 뿐, 가변 영역이 몇 px 이 될지는 모른다.

```
가변 영역 = 콘텐츠 폭 − 고정 폭 합

예) 문의 상세: 고정 897px (좌 300 + 패딩 16 + 구분선 1 + 서류 220 + Step 360)
    1280 뷰포트 → 콘텐츠 1060 → 상담 메모 163px  ← 못 씀
    1440 뷰포트 → 콘텐츠 1220 → 상담 메모 323px
```

**페이지 스스로 하한을 선언한다.** 값은 `고정 폭 합 + 가변 영역 최소치`.

```tsx
<div className="flex-1 overflow-x-auto overflow-y-hidden">
  <div className="flex h-full min-w-[1200px]">
    {/* 고정 패널들 + flex-1 가변 영역 */}
  </div>
</div>
```

`fullWidth` 라우트의 `main` 은 `overflow-hidden` 이라 스크롤 컨테이너를 **페이지 안에**
둬야 한다. 감싸는 위치는 헤더가 아니라 **본문**이다 (헤더는 대개 `flex-wrap` 으로 접힌다).

| 화면 | 고정 폭 합 | 하한 | 1440 |
|---|---|---|---|
| 문의 상세 · 리드 상세 | 817px | `1120` | 스크롤 없음 |
| 계약 상세 (4컬럼) | 1097px | `1400` | 스크롤 180px |
| 사고대차 리드 상세 | 비례 분할 | `720` | 스크롤 없음 |

숫자가 다른 건 페이지마다 고정 폭 합이 달라서다 — **공용 상수로 묶지 않는다.**

> 하한은 되도록 **1440 에서 스크롤이 안 생기는 값**(콘텐츠 1220 이하)으로 잡는다.
> 컬럼이 많아 불가피하면 스크롤을 택한다 — 가변 영역을 짜부시키는 것보다 낫다.

컬럼이 `flex-1` 비례 분할이면 이 문제가 없다(사고대차 계약 상세). 고정 폭 패널이
섞여 있을 때만 해당한다.

### `col-span-*` 이 섞인 그리드

`grid-cols-4` 안에 `col-span-3` 같은 조합이 있으면 **열 수만 바꾸면 배치가 무너진다.**
열 수를 바꿀 땐 `col-span` 도 같은 브레이크포인트로 함께 바꾼다.

```tsx
<div className="grid grid-cols-2 xl:grid-cols-4 gap-4">
  <div>차트</div>
  <div className="col-span-2 xl:col-span-3">표</div>
</div>
```

## 잘림 방지

폭이 모자랄 때 **글자가 잘리는 것**이 가장 흔한 깨짐이다. 카드에 `overflow-hidden` 이
있으면 넘친 숫자가 그냥 사라진다 — 금액이 잘리면 오독으로 이어진다.

- 금액·수치는 `leading-tight` + 줄바꿈 허용 (2줄이 잘림보다 낫다)
- 이름·제목 등 잘려도 되는 텍스트만 `truncate` + `title` 로 전체값 보존
- `leading-none` 은 줄바꿈 시 줄이 붙으므로 여러 줄이 될 수 있는 곳에는 쓰지 않는다

## 확인 방법

브라우저 개발자도구에서 뷰포트를 **1280 → 1440 → 1536** 세 폭으로 놓고 본다.
1280 에서 가로 스크롤이 생기면 하한 계산이 어긋난 것이다.

## 점진 적용

한 번에 전 화면을 고치지 않는다. **셸 하한이 붕괴를 이미 막고 있으므로**, 남은 그리드는
"셀 안 내용이 실제로 넘치는 곳"만 손댄다. 열 수가 많다고 무조건 대상이 아니다.

```
판단: 1024 기준 셀 폭을 계산 → 그 안에 가장 긴 값이 들어가나?
      금액·긴 라벨이면 손댄다. 숫자·짧은 라벨이면 그대로 둔다.
```

의미상 고정이라 **절대 반응형을 걸면 안 되는** 것도 있다 —
`period-range-picker.tsx` 의 `grid-cols-7` 은 달력의 요일 헤더다.

## 금지

- ❌ 페이지마다 `min-w-*` 를 따로 거는 것 (셸에서 이미 처리)
- ❌ 문제 없는 그리드에 일괄로 반응형 접두사 붙이기 (churn + col-span 파손)
- ❌ 커스텀 브레이크포인트 신설
- ❌ 모바일(`sm:` 미만) 대응 — 대상 기기가 아니다

> `grid-cols-5` 이상이 곧 잘못은 아니다. 1024 기준 셀 폭 안에 내용이 들어가면 그대로 둔다.
